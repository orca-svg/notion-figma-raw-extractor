# MCP Trace Studio · Figma 개발 플러그인

내부 파일럿에서 현재 열린 Figma Design 또는 FigJam 노드를 로컬 Trace Studio로 전달하는 읽기 전용 개발 플러그인입니다. Community 공개용 패키지가 아닙니다. 사용 순서는 [프로젝트 README](../../README.md#figma-연결)에 있고, 이 문서는 설치와 추출 규칙을 다룹니다.

## 빌드와 설치

프로젝트 루트에서 플러그인을 빌드합니다.

```bash
npm run build:plugin
```

Figma Desktop에서 `Plugins → Development → Import plugin from manifest…`를 열고 이 폴더의 `manifest.json`을 선택합니다. manifest의 ID는 로컬 개발용 placeholder이며 Community 배포 전에 Figma가 발급한 ID로 교체해야 합니다. 코드를 다시 빌드하면 플러그인을 닫았다가 다시 열어야 새 코드가 올라갑니다.

Trace Studio API가 로컬 포트 `8787`에서 실행 중이어야 합니다. 플러그인은 manifest에서 허용된 `http://localhost:8787`로 연결합니다. `/figma`에서 6자리 코드를 만든 뒤 플러그인에 입력합니다. 코드는 5분, 연결 토큰은 플러그인 메모리에만 유지됩니다.

연결 전 창은 `320×330`, 연결 후 대기 창은 `280×176`입니다. 플러그인이 HTTP long-poll로 다음 요청을 기다리므로 연결 후에도 창을 열어 두세요. 창을 닫으면 실행 중인 요청과 메모리 토큰이 종료되며 새 코드로 다시 페어링해야 합니다. Trace Studio가 이미 받은 결과에는 영향을 주지 않습니다.

Figma가 이전 manifest 오류를 캐시하면 개발 플러그인을 제거한 뒤 같은 `manifest.json`을 다시 가져옵니다. `devAllowedDomains`는 Figma의 로컬 개발 origin 형식에 맞춰 `http://localhost:8787`을 사용합니다.

## 공통 동작

- 링크의 file key와 열린 파일의 `figma.fileKey`가 다르거나 노드가 없으면 artifact를 보내기 전에 중단합니다.
- 노드 추출은 `getNodeByIdAsync()`와 `JSON_REST_V1`로 현재 노드 snapshot을 만듭니다. 페이지 추출은 `currentPage.loadAsync()` 후 최상위 프레임별 JSON·PNG를 만듭니다.
- 하위 image fill 원본과 이름이 icon/logo 후보인 SVG를 모읍니다(최대 50,000개). 내용이 같은 에셋은 하나로 합치고, 담지 못한 에셋은 사유별 개수로 보고합니다.
- PNG가 48MB를 넘으면 배율을 0.65배씩 줄여 첫 시도 포함 최대 4번 렌더링합니다.
- JSON 파트당 24MB(서버 수신 32MB), artifact당 48MB, 실행당 총 2GB까지입니다. 넘치는 페이지 트리는 서브트리 파트로 나누고, 노드 단건 추출만 500,000개 안전판을 둡니다. 큰 ZIP 조립을 위해 `start.command`·`start.bat`이 Node 힙을 `--max-old-space-size=8192`로 올립니다.
- 사용자가 실행하거나 질문한 순간에만 읽으며 `documentchange`를 감시하지 않습니다. 노드를 만들거나 수정하지 않고, 파일 원문과 이미지는 로컬 Trace Studio로만 보냅니다.
- 큰 페이지는 JSON 내보내기가 Figma 메인 스레드를 수십 초씩 붙잡아 하트비트가 늦습니다. 서버는 작업 중인 연결을 끊지 않고, 소식이 5분 넘게 없을 때만 실패로 봅니다.

## 화면 크기 후보

현재 페이지 추출은 먼저 이미지 없이 후보만 계산하고(`scanOnly`), 운영자가 고른 크기로 추출합니다.

- **이름**: 이름에 `Mobile`·`Tablet`·`Fold`·`Desktop`(한글 포함)이 붙은 프레임의 크기. 그 크기의 프레임이 모두 다른 화면 안에 있으면(예: 접기 카드 `Fold`) 컴포넌트로 보고 `ignoredDevices`에 남깁니다.
- **반복**: 이름은 없지만 이름으로 찾은 화면 밖에서 같은 크기(±8px)의 **프레임**이 3번 이상 나오는 크기(예: 미니모드 360×600 창). 패널·팝업·위젯은 주로 인스턴스로 쓰이므로 인스턴스는 세지 않습니다. 그 크기의 프레임 대부분이 다른 화면 크기 프레임을 둘 이상 품으면 기능 묶음으로 보고 제외합니다. 폴더 이름은 `repeated-<폭>x<높이>`입니다.
- **추정**: 이름도 반복도 없을 때만 폭 360~430·높이 600 이상을 모바일로 봅니다.
- **직접**: 위 후보가 화면을 하나도 찾지 못하면(기기 화면 없이 팝업·토스트·붙여 넣은 캡처로 된 명세 보드 등) 페이지에 두 번 이상 쓰인 200×200 이상 프레임·인스턴스 크기를 최대 12개 보여 줍니다. 기본으로 꺼져 있고, 켜면 그 크기를 화면처럼 찍습니다.
- **고르지 않음**: 크기를 하나도 켜지 않으면 화면·기능 묶음 이미지 없이 추출합니다. 빈 목록도 운영자의 선택이므로 플러그인이 크기를 다시 배우지 않습니다.
- 화면은 고른 크기에 맞는 **가장 바깥** 프레임입니다. 같은 크기의 자식 하나만 감싼 포장 프레임은 벗깁니다. 확인 화면에서 화면이 0개인 후보는 보이지 않습니다.
- 후보를 찾은 페이지와 추출할 때 열린 페이지가 다르면 추출을 거부합니다.

## 이미지

| 이미지 | 기준 | 크기 |
| --- | --- | --- |
| 화면 `screens/<기기>/` | 고른 크기에 맞는 가장 바깥 프레임 | 2배, 긴 변 8,192px 이하 |
| 기능 묶음 `groups/` | 화면을 둘 이상 품은 가장 안쪽 컨테이너. 소속 화면 좌표를 `screens.json`에 기록 | 긴 변 4,096px 이하 |
| 페이지 배치도 `screenshots/` | 최상위 노드 | 긴 변 2,048px 이하, 원본보다 키우지 않음 |

화면은 Figma에서 보이는 그대로 찍습니다. 뷰포트가 가린 스크롤 영역은 이미지로 꺼내지 않고 노드 JSON에만 있습니다. 반대로 clip이 꺼진 프레임 밖으로 보이는 내용은 이미지에 들어갑니다.

**원점 보정.** `exportAsync`는 프레임 박스가 아니라 실제로 그려진 범위를 내보냅니다. 그림자나 넘친 내용이 있으면 PNG가 프레임보다 커지고 이미지의 (0, 0)이 프레임 원점과 어긋납니다(NH 주식 페이지에서 375×812 화면이 880×1,684로 나와 x 62px 밀림). 그래서 프레임 원점이 이미지 안에 놓인 위치를 `renderOffset`(Figma 단위)으로 남기고, 서버가 픽셀 `offset`으로 바꿔 모든 `imageRect`에 반영합니다. Figma 좌표를 직접 옮길 때는 `rect × scale + offset`입니다.

## Figma 기본 주석

노드에 단 기본 주석(Annotation)을 `screens.json`의 `annotations`에 둡니다.

- **내용**: 평문 `label`, `labelMarkdown`, 고정 속성 종류(`properties`), 카테고리 이름. 카테고리 이름은 노드 JSON에 없어 `figma.annotations.getAnnotationCategoriesAsync()`로 읽습니다.
- **위치**: 붙은 노드의 조상에서 화면(`screenNodeId`)과 기능 묶음(`groupNodeId`)을 정합니다. `rect`는 화면 원점(화면 밖이면 묶음, 둘 다 없으면 페이지) 기준 Figma 단위, `imageRect`는 그 이미지 픽셀입니다.
- **속도**: 주석이 붙은 노드는 이미 내보낸 노드 JSON에서 찾고 그 노드만 다시 읽습니다. 노드마다 주석을 물으면 8만 노드 페이지에서 10분 넘게 걸렸습니다.
- 디자인 안에 글자로 적은 설명 블록(예: `Description` 프레임)은 Figma 주석이 아닙니다. 번호 배지로 이어지는 설명은 `spec-marks.json`에, 나머지는 `nodes/`의 TEXT 노드에만 남습니다.

## 번호 배지와 설명 칸 (`spec-marks.json`)

기획서는 화면 위에 `01`·`E1` 같은 번호 배지를 얹고 같은 번호의 설명을 따로 적습니다. 현재 페이지 추출은 둘을 이어 `spec-marks.json`에 남기며, 명세 배지를 쓰지 않는 페이지면 파일을 만들지 않습니다.

- **배지 고르기**: 모양이 아니라 쓰임새로 고릅니다. 같은 컴포넌트가 글자만 있는 줄(설명 칸)과 화면 위(표시)에 함께 쓰이고 번호가 양쪽에서 맞아야 명세 배지입니다. 종목 태그·순위 숫자처럼 생김새만 비슷한 UI는 빠집니다.
- **설명이 맡는 영역**: 보드 안의 설명 열은 그 보드 전체를 맡습니다. 보드 밖에 설명 열이 여럿 있으면, 같은 파일 안의 확실한 예에서 설명이 표시의 어느 쪽에 붙는지 배워(`layout.side`) 그 방향의 띠를 맡깁니다. 배울 예가 없으면 가장 가까운 영역을 맡기되, 두 번째보다 두 배 이상 가까울 때만 정합니다.
- **짝 잇기**: 같은 번호의 설명 칸을 모두 `candidates`에 두고, 영역 안(`inScope: true`) 후보 가운데 근거가 뚜렷할 때만 `status: linked`로 확정합니다. 근거 순서는 후보 하나 → 트리 근접도 → 같은 글 → 내용 겹침 → 상대 거리입니다.
- **확인 필요·설명 없음**: 영역 안 후보를 가르지 못하면 `ambiguous`, 영역 안에 같은 번호 설명이 없으면 `unlinked`입니다. 다른 영역의 같은 번호 설명은 `inScope: false` 참고 후보로만 남깁니다.
- **좌표·원문**: `rect`는 화면 기준 Figma 단위, `imageRect`는 화면 이미지 픽셀입니다. 곁에 테두리 사각형이 있으면 그 영역을 가리킵니다. 설명 원문은 목록 서식을 되살린 마크다운(`markdown`)입니다.

## 화면 뷰어 (`screens/screens.html`)

색인을 파일 안에 담고 이미지는 번들 안 상대 경로(`../`)로 읽어 서버나 인터넷 없이 열립니다. 이 파일만 따로 옮기거나 폴더 구조를 바꾸면 이미지가 보이지 않습니다.

- `화면`·`기능 묶음` 탭, 기기 선택, `주석 있는 화면만`, 이름·경로·주석 검색
- 화면을 누르면 주석 목록과 이미지 위 주석 위치(번호 상자)가 나옵니다. 기능 묶음을 누르면 그 안의 화면 위치가 상자로 표시되고, 상자를 누르면 그 화면으로 넘어갑니다.
- 번호 배지 짝(`spec-marks.json`)은 그리지 않습니다. 다음 도구가 읽는 색인입니다.
